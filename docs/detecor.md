#### Общий принцип: «Detect -> Confirm -> Create»

1. **Detect** -- после каждого ответа ассистента фоновый LLM-вызов проверяет, есть ли в диалоге кандидат на сущность

2. **Confirm** -- показываем пользователю chip/hint с предложением

3. **Create** -- создаём только после действия пользователя (или через таймаут с undo, если confidence очень высокий)

## 1\. Контексты чата и их влияние на логику

В Delёz чат существует в нескольких контекстах, которые определяют поведение Detector-агента:

| Контекст                          | Где открыт чат                              | Поведение Detector                                     |
|-----------------------------------|---------------------------------------------|--------------------------------------------------------|
| **Пространство события**          | Страница конкретного события -> "К чату"    | Агрессивное обогащение: любые детали -> в поля события |
| **Пространство ризомы / главная** | Главный экран "Как ты себя чувствуешь?"     | Стандартное: создание новых сущностей                  |
| **Произвольный чат**              | Любой открытый тред без привязки к сущности | Консервативное: только высокий confidence              |

:::quote 

**Ключевое правило:** если чат открыт со страницы события через кнопку "К чату ->", Detector по умолчанию предполагает, что пользователь говорит *об этом событии*, и не предлагает создать новое -- только обогащает существующее.

:::

## 2\. Трёхфазный флоу создания события

```
Фаза 1: DETECT          Фаза 2: CONFIRM            Фаза 3: CREATE
─────────────────       ────────────────────────    ──────────────
После каждого           Показываем chip             После действия
assistant-ответа   →    пользователю           →    пользователя
(фоновый вызов)         (или таймаут)               (или явного запроса)
```

## 3\. Сценарий A -- Главный экран / свободный чат

### 3\.1 Пользователь рассказывает о ситуации из жизни

**Триггер:** пользователь пишет сообщение с признаками реального события (прошедшее время, эмоциональный контекст, конкретная ситуация).

**Шаг 1 -- Ассистент отвечает на сообщение** в своём обычном режиме: поддерживает, задаёт уточняющие вопросы, рефлексирует.

**Шаг 2 -- Detector запускается фоново** (async, параллельно с ответом ассистента).

Detector анализирует последние 6–10 сообщений диалога. Возможные результаты:

| Confidence   | Действие                             |
|--------------|--------------------------------------|
| \< 0.65      | Ничего не показывать                 |
| 0\.65 – 0.84 | Показать мягкую подсказку (см. §3.2) |
| ≥ 0.85       | Показать chip создания (см. §3.3)    |

---

### 3\.2 Мягкая подсказка (confidence 0.65 – 0.84)

Появляется как **маленький тег** под последним сообщением ассистента, не прерывает диалог:

```
[ответ ассистента]

  💾 Похоже на событие — сохранить?
```

-  Время жизни: исчезает после следующего сообщения пользователя

-  Клик по тегу -> разворачивает chip создания (см. §3.3)

-  Если пользователь игнорирует -> не появляется снова в этом диалоге по этой теме

---

### 3\.3 Chip создания (confidence ≥ 0.85)

Появляется **после ответа ассистента** как отдельный блок под сообщением:

```
┌─────────────────────────────────────────────────────┐
│ 📌  Сохранить как событие?                          │
│     "Конфликт с коллегой из-за дедлайна"            │
│                                                     │
│  [Сохранить]     [Переименовать]     [Не сейчас]    │
└─────────────────────────────────────────────────────┘
```

**Поведение кнопок:**

-  **Сохранить** -> событие создаётся немедленно с автозаполненными полями из контекста диалога -> ассистент подтверждает: *"Добавила в события. Можешь открыть его и дополнить детали ->"*

-  **Переименовать** -> поле title становится редактируемым inline, затем Сохранить

-  **Не сейчас** -> chip скрывается, больше не появляется в этом диалоге по этой теме

**Таймаут:** chip автоматически скрывается через **60 секунд** без действия. Событие **не создаётся**.

---

### 3\.4 Ручной запрос пользователя

Пользователь может явно попросить создать событие. Detector обрабатывает это как intent с confidence = 1.0, минуя chip:

**Фразы-триггеры (примеры, не исчерпывающий список):**

-  *"Запомни это как событие"*

-  *"Сохрани это"*

-  *"Добавь в мой дневник"*

-  *"Хочу зафиксировать этот момент"*

**Поведение:** ассистент немедленно создаёт событие и подтверждает в ответе:

:::quote 

*"Сохранила как событие «Разговор с мамой о планах». Дата: сегодня. Открыть ->"*

:::

## 4\. Сценарий B -- Чат в пространстве ризомы (главный экран)

На главном экране три подсказки: "Что тебя сейчас тревожит?", "Какие цели вдохновляют?", "Как прошёл твой день?".

Если пользователь нажимает **"Как прошёл твой день?"** -> чат открывается с контекстом-предположением `probable_entity_type: event`. Detector с первого же сообщения настроен на извлечение событий, confidence threshold снижается до **0\.70** (более агрессивный).

---

## 5\. Сценарий C -- Чат открыт со страницы события ("К чату ->")

Это самый важный сценарий: пользователь уже находится на странице конкретного события и жмёт "К чату ->". В этом случае:

-  `context_entity_id` = ID текущего события передаётся в thread

-  Detector **не предлагает создать новое событие**

-  Detector работает в режиме **обогащения**: любые детали из диалога -> в поля существующего события

### 5\.1 Автоматическое тихое обогащение

Если пользователь говорит что-то, что явно относится к полям события, -- данные обновляются **без chip и без подтверждения**:

| Что сказал пользователь                      | Что обновляется                          |
|----------------------------------------------|------------------------------------------|
| *"Это было примерно в 3 дня"*                | `eventdate` (время)                      |
| *"Мне было очень тревожно"*                  | `sentiment_score`, связанный Affect      |
| *"Это повлияло на мои отношения с командой"* | `description` / новая `relatedSituation` |
| *"Оцениваю это на 7/10 по интенсивности"*    | `intensitymetrics`                       |

Обновление происходит тихо. В интерфейсе -- лёгкая анимация "пульса" у иконки события в сайдбаре, сигнализирующая что данные обновились.

### 5\.2 Chip при существенном новом контенте

Если Detector обнаруживает **ключевое поле, которое было пустым** (например, `description` события было пустым, и пользователь только что хорошо его описал) -- показывается chip:

```
┌────────────────────────────────────────────────────┐
│ ✏️  Обновить описание события?                     │
│  "Почувствовал, что давление накопилось за         │
│   несколько дней, а не из-за одного момента"       │
│                                                    │
│  [Добавить к событию]           [Пропустить]       │
└────────────────────────────────────────────────────┘
```

## 6\. Автозаполнение полей события из контекста диалога

При создании события через чат Detector извлекает следующие поля:

| Поле события      | Источник в диалоге                                                | Fallback                |
|-------------------|-------------------------------------------------------------------|-------------------------|
| `title`           | Ключевая фраза из сообщения пользователя                          | "Событие \[дата\]"      |
| `eventdate`       | Временные маркеры ("вчера", "сегодня", "в пятницу")               | Дата текущего сообщения |
| `description`     | Развёрнутый контекст из 2–3 последних сообщений                   | Пусто                   |
| `importance`      | Интенсивность языка (слова с высоким аффектом = высокая важность) | 0\.5                    |
| `sentiment_score` | Тональность сообщений пользователя                                | нейтральный             |

После создания события через chip -- **страница события открывается в новой вкладке** (или sheet поверх чата), где пользователь может сразу дополнить поля вручную.

---

## 7\. Что НЕ является триггером для создания события

Detector должен явно игнорировать следующие паттерны:

-  Технические вопросы ("помоги решить задачу", "что такое...")

-  Гипотетические рассуждения ("а вот если бы я...")

-  Вопросы к ассистенту о его функциях

-  Записи о других людях без личного эмоционального контекста автора

-  Дублирование: если в диалоге уже был создан chip по этой теме и пользователь нажал "Не сейчас" -- не показывать снова

## 8\. Логика сессии: память внутри диалога

Detector ведёт **сессионный стейт** внутри thread:

```json
{
  "proposed_entities": [
    {
      "type": "event",
      "proposed_title": "Конфликт с коллегой",
      "status": "declined",
      "message_id": "msg-045"
    }
  ],
  "created_entities": [
    {
      "type": "event",
      "entity_id": "ev-123",
      "created_at": "2026-04-14T09:30:00Z"
    }
  ]
}
```

Правила:

-  Если статус `declined` -> не предлагать по этой теме снова

-  Если уже создано `ev-123` -> Detector переключается в режим обогащения для этого события

-  Стейт сбрасывается при создании нового thread

```

  "context": {

  "entities": [
    {

      "confidence": 0.91,
```

## 10\. Edge cases

| Ситуация                                                 | Поведение                                                                                          |
|----------------------------------------------------------|----------------------------------------------------------------------------------------------------|
| Пользователь описал два разных события в одном сообщении | Detector предлагает создать только **одно** (с наибольшим confidence). Второе -- в следующем цикле |
| Chip показан, пользователь продолжает диалог не нажимая  | Chip скрывается через 60 сек. Диалог продолжается нормально                                        |
| Пользователь нажал "Сохранить", но интернет пропал       | Оптимистичный UI: показываем "Сохранено", повторная попытка в фоне. При ошибке -- уведомление      |
| Пользователь написал "не надо" текстом                   | Detector распознаёт как отклонение, chip скрывается (если был), статус -> `declined`               |
| Два чипа одновременно (событие + цель)                   | Показываем только один -- с наибольшим confidence. Второй -- после завершения первого              |
