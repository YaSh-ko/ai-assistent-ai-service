## 1\. Структура концепта в данных

Концепт хранится в двух местах одновременно:

### Neo4j -- узел Concept

```
Concept {
  id:          UUID
  name:        STRING       ← сам вывод (зелёный текст)
  description: TEXT         ← развёрнутое объяснение вывода
  relevance:   FLOAT 0-1    ← насколько важен для пользователя
  userid:      STRING
  createdat:   DATETIME
  updatedat:   DATETIME
}
```

### PostgreSQL -- поля в таблице `entries` (для страницы события)

```
negativeImpacts[]    ← основания / что пошло не так (красный)
  - id
  - title            ← текст красного блока
  - severity         ← 1-10

transformations[]    ← сам концепт-вывод (зелёный)
  - id
  - title            ← текст зелёного блока
  - category         ← behaviorChange | beliefChange | relationshipRule | ...
```

### Связь в Neo4j

```cypher
(entry)-[:MENTIONS {context, relevance, mentionedat}]->(concept)
```

Если концепт был рождён из анализа:

```cypher
(analysis)-[:PRODUCES {emergedat, confidence}]->(concept)
```

## 2\. Когда концепт появляется в диалоге

Концепт -- это **вторичная сущность**: он не существует без контекста, из которого был извлечён. Поэтому Detector ищет его только при наличии двух сигналов одновременно:

| Сигнал                                   | Пример фразы                                                                             |
|------------------------------------------|------------------------------------------------------------------------------------------|
| **Негативный опыт / причина**            | "Меня обесценили", "Организация была ужасной", "Я потерял связь с командой"              |
| **Вывод / намерение изменить поведение** | "Больше не буду...", "Теперь я понимаю что...", "Решила для себя что...", "Надо было..." |

Только при наличии **обоих сигналов** Detector считает, что обнаружен концепт. Один сигнал без другого -> не концепт (просто эмоция или намерение).

## 3\. Режимы фиксации концепта

### Режим A -- Автоматический (тихий)

**Условия:**

-  Чат открыт в пространстве конкретного события ("К чату ->")

-  В диалоге ясно прослеживается и основание, и вывод

-  Confidence Detector ≥ 0.88

**Поведение:**

1. Концепт создаётся в Neo4j без уведомления

2. `negativeImpacts[]` и `transformations[]` обновляются в PostgreSQL (PATCH `/api/v1/entries/{id}`)

3. На странице события появляются красные и зелёные блоки

4. В чате -- никакого chip. Лёгкая анимация пульса у иконки события в сайдбаре

**Когда уместен:** когда пользователь явно и развёрнуто сформулировал вывод -- нет смысла спрашивать подтверждения.

---

### Режим B -- Chip подтверждения

**Условия:**

-  Confidence 0.72–0.87

-  Чат в свободном режиме (не привязан к событию)

-  Или: концепт новый, не похожий на уже сохранённые

**Как выглядит chip:**

```
┌──────────────────────────────────────────────────────────┐
│  💡  Кажется, ты сформулировала важный вывод             │
│                                                          │
│  Почему:                                                 │
│  · Плохая организация проекта                            │
│  · Обесценивание работы                                  │
│  · Потеря возможности показать результат                 │
│                                                          │
│  Вывод:                                                  │
│  "Больше не участвую в проектах с плохой организацией"   │
│                                                          │
│  [Сохранить вывод]    [Уточнить]    [Не сейчас]          │
└──────────────────────────────────────────────────────────┘
```

**Поведение кнопок:**

-  **Сохранить вывод** -> концепт создаётся в Neo4j + обновляется страница события

-  **Уточнить** -> ассистент задаёт уточняющий вопрос: *"Хочешь переформулировать вывод своими словами?"* -> пользователь пишет текст -> сохраняется его формулировка

-  **Не сейчас** -> chip скрывается, статус `declined`, в этом диалоге по этой теме больше не предлагать

---

### Режим C -- Ручной запрос

Пользователь явно просит зафиксировать вывод:

**Фразы-триггеры:**

-  *"Запомни этот вывод"*

-  *"Сохрани это как правило"*

-  *"Хочу зафиксировать этот урок"*

-  *"Это важное понимание, не забудь"*

**Поведение:** Detector с confidence = 1.0. Если в диалоге есть явные основания (красные блоки) -- они автоматически подтягиваются. Если нет -- ассистент спрашивает: *"Что привело тебя к этому выводу?"* -> ответ пользователя -> становится `negativeImpacts`.

## 4\. Диалоговый сценарий -- полный пример

:::quote 

**Контекст:** чат открыт со страницы события "Провальная презентация проекта"

:::

**Пользователь:** "Это был кошмар. Мы вышли вообще без подготовки, клиент не понял что мы сделали, и ещё Артём сказал что это был бесполезный проект. Я выбежала из чата в середине."

**Ассистент:** *(отвечает эмпатично, задаёт вопросы)*

*\[Detector фоновый вызов -- confidence 0.71, ждёт продолжения\]*

**Пользователь:** "Больше никогда не буду участвовать в проектах где нет чёткого ТЗ с самого начала. И с Артёмом работать не хочу -- он склонен обесценивать чужой труд."

**Ассистент:** *(отвечает на содержание)*

*\[Detector второй вызов -- confidence 0.91. Два сигнала найдены.\]*

*-> Режим A: тихое создание*

**Что создаётся автоматически:**

```json
negativeImpacts: [
  { "title": "Отсутствие чёткого ТЗ", "severity": 8 },
  { "title": "Обесценивание работы коллегой", "severity": 7 },
  { "title": "Эмоциональный выход из чата", "severity": 6 }
]

transformations: [
  { "title": "Не участвовать в проектах без чёткого ТЗ", "category": "behaviorChange" },
  { "title": "Избегать работу с людьми, склонными обесценивать труд", "category": "relationshipRule" }
]
```

**Neo4j Concept узлы:**

```
Concept { name: "Проекты только с чётким ТЗ", relevance: 0.9 }
Concept { name: "Фильтр по ценностям в командах", relevance: 0.85 }

(entry)-[:MENTIONS {relevance: 0.9, context: "..."}]->(concept)
```

На странице события появляются красные и зелёные блоки (как на фото).

## 5\. Особый случай: концепт без привязанного события

Если пользователь формулирует вывод в свободном чате, не в контексте конкретного события:

1. Detector предлагает chip (Режим B)

2. После сохранения ассистент спрашивает: *"Хочешь привязать этот вывод к какому-то событию в твоей жизни?"*

3. Пользователь может выбрать из последних 5 событий или сказать "нет" -> концепт сохраняется как **автономный** (не связанный с Entry)

4. На ризоме такой концепт отображается как отдельный узел без входящих связей от Entry

## 6\. Эволюция концепта: EVOLVESINTO

Если Detector обнаруживает, что новый концепт противоречит или уточняет уже сохранённый -- вместо создания нового предлагается эволюция:

```
┌──────────────────────────────────────────────────────────────┐
│  🔄  Этот вывод уточняет твоё более раннее правило           │
│                                                              │
│  Было:   "Избегать токсичных людей на работе"   (март 2025)  │
│  Стало:  "Фильтровать по ценностям с первой встречи"         │
│                                                              │
│  [Обновить правило]    [Сохранить как отдельное]    [Отмена] │
└──────────────────────────────────────────────────────────────┘
```

При "Обновить правило" создаётся связь:

```cypher
(oldConcept)-[:EVOLVESINTO {
  evolutiontype: "refinement",
  evolvedat: datetime(),
  description: "уточнение через новый опыт"
}]->(newConcept)
```

## 7\. Правила: что НЕ является концептом

| Паттерн                                             | Почему не концепт       | Пример                                     |
|-----------------------------------------------------|-------------------------|--------------------------------------------|
| Только эмоция, без вывода                           | Нет трансформации       | "Мне было очень плохо"                     |
| Только вывод, без основания                         | Нет контекста           | "Надо больше отдыхать" (без истории)       |
| Чужой опыт                                          | Нет личного переживания | "Говорят, что лучше не работать с..."      |
| Технические инструкции                              | Нет рефлексии           | "Нужно добавить валидацию в форму"         |
| Повтор уже сохранённого концепта (>0.85 similarity) | Дубликат                | Обогатить существующий, не создавать новый |

## 8\. API-взаимодействие

### 8\.1 Detector возвращает концепт

```json
POST /api/v1/ai/detect-entities
Response:
{
  "entities": [
    {
      "type": "concept",
      "confidence": 0.91,
      "name": "Проекты только с чётким ТЗ",
      "description": "Вывод сделан после провала презентации...",
      "grounds": [
        { "title": "Отсутствие ТЗ", "severity": 8 },
        { "title": "Обесценивание результата", "severity": 7 }
      ],
      "transformations": [
        { "title": "Не брать проекты без ТЗ", "category": "behaviorChange" },
        { "title": "Фильтровать команды по ценностям", "category": "relationshipRule" }
      ],
      "similar_existing": [
        { "concept_id": "concept-045", "name": "Токсичные люди на работе", "similarity": 0.71 }
      ]
    }
  ]
}
```

### 8\.2 Создание концепта

```
POST /api/v1/concepts
Body:
{
  "name": "Проекты только с чётким ТЗ",
  "description": "...",
  "relevance": 0.9,
  "userid": "user-xyz",
  "source_entry_id": "entry-123",
  "source_thread_id": "thread-abc"
}
```

### 8\.3 Обновление события (negativeImpacts + transformations)

```
PATCH /api/v1/entries/{entry_id}
Body:
{
  "negativeImpacts": [
    { "title": "Отсутствие ТЗ", "severity": 8 },
    { "title": "Обесценивание", "severity": 7 }
  ],
  "transformations": [
    { "title": "Не брать проекты без ТЗ", "category": "behaviorChange" }
  ]
}
```

### 8\.4 Связь Entry -> Concept в Neo4j

```
POST /api/v1/graph/relationships
Body:
{
  "from": { "type": "Entry", "id": "entry-123" },
  "to": { "type": "Concept", "id": "concept-789" },
  "relationship": "MENTIONS",
  "properties": {
    "context": "Провальная презентация, апрель 2026",
    "relevance": 0.9,
    "mentionedat": "2026-04-14T00:00:00Z"
  }
}
```

## 9\. Визуальный результат на странице события

После сохранения концепта страница события обновляется и показывает блоки (как на фото):

![](./tz-izvlechenie-konceptov-cherez-chat-delez.png){width=338px height=783px}

**Секция "Что случилось?"** -> красные таблетки:

-  Плохая организация

-  Обесценивание работы

-  Эмоциональная реакция (выход из чата)

**Секция "✨ Трансформация ✨"** -> зелёные таблетки:

-  Больше не участвуем в проектах с плохой организацией

-  Не выходим из чатов в стрессовых ситуациях, а обосновываем все по пунктам

-  Избегаем общение с людьми, склонными к обесцениванию труда

Если секции были пустыми до сохранения -- они появляются с анимацией fade-in.
